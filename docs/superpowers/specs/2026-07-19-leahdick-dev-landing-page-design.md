## 5. ארכיטקטורה טכנית

**Astro, אתר סטטי, פרוס ב‑Cloudflare Pages.**

### 5.1 הפרדת תוכן ממבנה

הלב של הארכיטקטורה. כל הטקסטים יושבים ב‑`src/data/content.ts` שמייצא שני אובייקטים — `he` ו‑`en` — הנשלטים על ידי אותו טיפוס `SiteContent`. הקומפוננטות מקבלות אובייקט תוכן כ‑prop ואינן יודעות באיזו שפה מדובר.

התוצאה: שינוי טקסט לא נוגע ב‑markup, הטיפוס המשותף מבטיח ששתי השפות לא יתפצלו בשקט, והוספת שפה שלישית בעתיד היא אובייקט נוסף ולא שכפול קומפוננטות.

### 5.2 מבנה קבצים

```
src/
  data/content.ts          — SiteContent, he, en
  layouts/Layout.astro     — html, head, meta, dir/lang
  components/
    Hero.astro
    Capabilities.astro
    Projects.astro
    ProjectCard.astro
    Experience.astro
    TechStack.astro
    Education.astro
    Contact.astro
    LangToggle.astro
  pages/
    index.astro            — עברית
    en.astro               — אנגלית
  styles/global.css
public/
  logo-ld.png
  favicon
  cv/
```

כל קומפוננטה אחראית לסקציה אחת, מקבלת את פרוסת התוכן שלה, וניתנת להסתכלות ולבדיקה בנפרד.

### 5.3 פריסה ודומיין

הדומיין `leahdick-dev.com` מנוהל ב‑Cloudflare, ולכן האחסון נעשה ב‑Cloudflare Pages — הכל אצל ספק אחד.

**החיבור:** יצירת פרויקט Pages המחובר לריפו `LallyDik/Landing-page`, עם פקודת build `npm run build` ותיקיית פלט `dist`. דיפלוי אוטומטי בכל push ל‑main, ו‑preview לכל branch. הדומיין מחובר דרך מסך Custom Domains — Cloudflare יוצר את רשומות ה‑DNS בעצמו, ותעודת ה‑SSL מונפקת ומתחדשת אוטומטית.

**היתרון על פני ספק חיצוני:** אין רשומות DNS ידניות, אין שאלה של proxy מול DNS‑only, ואין נקודת כשל בין שני שירותים. זו הסיבה שהמסלול הזה נבחר על פני Vercel.

**נדרשת גישה** לחשבון ה‑Cloudflare ולחשבון ה‑GitHub לצורך חיבור הריפו — שלב חד‑פעמי שמתבצע בסוף, אחרי שהאתר בנוי ונבדק מקומית.

### 5.4 SEO ונגישות

- `title` ו‑`meta description` ייעודיים לכל שפה
- Open Graph image שנוצרת מהלוגו והגרדיאנט
- JSON‑LD מסוג `Person` עם שם, תפקיד, קישורים ופרטי קשר
- `sitemap.xml`, `robots.txt`, ותגי `hreflang` הדדיים
- ניגודיות צבע העומדת ב‑WCAG AA על הרקע הכהה
- HTML סמנטי, ניווט מקלדת מלא, וטקסט חלופי לכל תמונה
